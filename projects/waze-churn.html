Waze Churn Prediction

An analysis of app-use patterns and model recall to explore how churn risk might be identified for a second iteration.

OverviewBusiness problemObjectiveApproachToolsFindingsRecommendationsEvidence

Overview

This practice project uses a fictional teaching dataset created for learning. It applies the PACE framework to examine user churn and model performance.

Business problem

The project explored whether patterns in app use could help identify users at risk of stopping their use of Waze, and what further data or analysis might be needed.

Objective

Examine churn behavior, test candidate classification models, and assess whether their ability to identify churned users is sufficient to guide another analysis iteration.

Approach

  1. Used exploratory analysis and hypothesis testing to examine app-use patterns and compare iPhone and Android users.
  2. Fit logistic regression, Random Forest, and XGBoost models within the PACE framework.
  3. Compared recall and reviewed the role of engineered features in the model results.

Tools

  • Python
  • Hypothesis testing
  • Logistic regression
  • Random Forest
  • XGBoost
  • PACE framework

Findings

  • 18% of users in the dataset churned.
  • Churned users drove much farther per driving day but used the app on fewer days.
  • The difference in drives between iPhone and Android users was not statistically significant.
  • Logistic regression recall was 9%; XGBoost recall was 17%. Engineered features were important to the model results.

Recommendations

Run a second iteration with more data and better features. The current recall results indicate that the models may miss many users who churn; additional work is needed before relying on predictions for decisions.
